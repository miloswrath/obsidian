## 1️⃣ Broad Framing (Motivation + Fit)

### 1.1 Opening

**“What about this role stood out to you, and why do you want to work in a research lab building technical systems?”**

**Evaluates:**

- Intrinsic motivation
    
- Alignment with “not low-effort involvement” expectation
    
- Understanding of infrastructure vs. feature-building
    

**Green flags**

- Mentions systems, pipelines, infrastructure, reproducibility
    
- Curious about research data
    
- Wants to build tools used by others
    

**Red flags**

- Vague “resume builder”
    
- Interested only in ML buzzwords
    
- No mention of systems or research context
    

---

### 1.2 Long-Term Fit

**“How does this position fit into your long-term goals?”**

**Evaluates:**

- Strategic thinking
    
- Whether they’ll stay engaged beyond novelty
    
- Growth alignment (co-authorship, mentorship, etc. )
    

Follow-up:

- “Where do you want to be in 3–5 years?”

## 2️⃣ Technical Core – Python & Systems Thinking

### 2.1 Python Proficiency (Conceptual)

**“Walk me through a project you built that required structuring real data.”**

Follow-ups:

- How did you structure the project?
    
- How did you handle edge cases?
    
- How did you validate correctness?
    
- What broke the first time?
    

**Evaluates**

- Depth vs. surface-level scripting
    
- Debugging experience
    
- Familiarity with structured systems (not just notebooks)
    

---

### 2.2 Data Engineering Thinking

Given the lab works with multimodal data (accelerometer, heart rate, MRI, assessments ):

**“Suppose you receive 100 participant accelerometer files, some missing timestamps, some corrupted. What steps would you take before analysis?”**

Looking for:

- QA mindset
    
- Logging
    
- Validation scripts
    
- Reproducibility
    
- Automated checks
    

This reveals:

- Systems mindset
    
- Research integrity awareness
    
- Determination to build durable tools
    

---

### 2.3 Quick Thinking (On-the-Spot Scenario)

**“You push a change to a data pipeline and it silently corrupts output for two weeks. What do you do?”**

Evaluate:

- Accountability
    
- Version control awareness
    
- Git rollback?
    
- Audit logs?
    
- CI/CD thinking (GitHub Actions mentioned in stack )
    
- Communication

### 2.4 Debugging Depth

This measures:

- Determination
